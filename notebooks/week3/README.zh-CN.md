# 第 3 周：关键词搜索优先——关键基础

> **🚨 90% 的问题：** 大多数 RAG 系统一开始就直接使用向量搜索，却忽略了支撑优秀检索系统的基础。我们要用正确的方式来构建！

本目录包含 arXiv 论文助手项目第 3 周的学习资料。本周将使用 OpenSearch 和 BM25 评分，实现专业 RAG 系统赖以工作的**关键词搜索基础**。

## 🎯 为什么先做关键词搜索？

**专业路径：** 与一开始就使用向量嵌入的教程不同，我们会先构建成熟企业采用的搜索基础：

1. **🔍 精确匹配能力：** 关键词非常适合查找特定技术术语、论文 ID 和准确短语
2. **📊 结果可解释：** 你能准确理解某篇论文为何会被检索出来
3. **⚡ 快速高效：** BM25 计算速度快，而且不需要昂贵的嵌入模型
4. **📈 生产实践：** Elasticsearch、Algolia 等公司及企业搜索产品都以关键词搜索为基础

**学习路径：**

```text
第 3 周：掌握 BM25 关键词搜索    ← 你在这里
第 4 周：加入智能文档切分
第 5 周：引入向量嵌入，实现混合检索
第 6 周：优化完整系统
```

## 已实现的主要功能

### 🔍 **生产级搜索系统**

- **BM25 评分**：业界标准的相关性排序算法
- **多字段搜索**：查询标题（3 倍权重）、摘要（2 倍权重）和正文（1 倍权重）
- **高级筛选**：分类筛选、日期范围和自定义字段查询
- **实时高亮**：使用 HTML 标记在结果中高亮搜索词
- **分页支持**：使用 size/from 参数高效处理大型结果集

### 🏗️ **简洁架构实现**

- **工厂模式**：在所有组件中采用一致的服务创建方式
- **依赖注入**：结合 FastAPI 生命周期妥善管理服务生命周期
- **查询构建器模式**：灵活构建复杂操作所需的搜索查询
- **错误处理**：全面管理异常并支持优雅降级

### 📊 **性能与监控**

- **搜索低于 100ms**：为实时应用优化查询性能
- **健康监控**：监控集群状态、索引统计信息和服务可用性
- **资源限制**：限制 PDF 处理，避免内存问题
- **可扩展性**：采用支持横向扩展的设计模式

### 🔧 **开发最佳实践**

- **类型安全**：整个代码库都使用完整的类型提示
- **测试**：使用贴近真实的数据场景完成端到端验证
- **文档**：提供完整的文档字符串和架构说明
- **代码质量**：遵循第 1～2 周实现中已经确立的模式
