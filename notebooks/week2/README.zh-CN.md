# 第 2 周：arXiv API 集成与 PDF 处理

本目录包含 arXiv 论文助手项目第 2 周的学习资料，重点是构建核心数据摄取流水线，为 RAG 系统持续提供最新学术内容。

## 内容

### `week2_arxiv_integration.ipynb`

这是一份完整的 Jupyter Notebook，将引导学生学习：

1. **基础设施验证**
   - 验证第 1 周的所有服务是否正常运行
   - 检查容器健康状态并验证全新构建
   - 为第 2 周的组件配置环境

2. **arXiv API 集成**
   - 构建具有限流和重试逻辑的健壮客户端
   - 实现基于日期的筛选，按目标获取论文
   - 遵循 API 使用规范，测试 CS.AI 分类搜索

**数据流水线概览：**

- **MetadataFetcher**：🎯 协调整条流水线的主编排器
- **ArxivClient**：带重试逻辑的限流获取客户端（每次间隔 3 秒）
- **PDFParserService**：解析科学论文 PDF 并提取结构化内容
- **PaperRepository**：集成 PostgreSQL 并执行 upsert 操作
- **Airflow DAG**：自动执行每日摄取工作流

3. **PDF 处理流水线**
   - 下载并缓存 PDF 文件，同时妥善处理错误
   - 使用 Docling 解析科学论文 PDF 并提取结构化内容
   - 通过回退机制妥善处理解析失败

4. **数据库集成**
   - 在 PostgreSQL 中存储论文元数据和内容
   - 实现 upsert 逻辑以避免重复数据
   - 测试检索和查询操作

5. **完整流水线测试**
   - 对从 arXiv API 到数据库存储的端到端流程进行测试
   - 测试错误处理与优雅降级
   - 分析性能指标和成功率

6. **生产就绪**
   - 验证 Airflow DAG 状态
   - 提供错误日志记录和监控能力
   - 可用于自动执行每日数据摄取

## 核心技术与服务

### 本周构建的核心服务

- **arXiv API 客户端**——通过智能限流获取 CS.AI 论文
- **PDF 解析器（Docling）**——从科学论文 PDF 中提取结构化内容
- **元数据获取器**——编排完整的处理流水线
- **数据库仓储**——通过 SQLAlchemy 处理 PostgreSQL 操作

### 基础设施依赖（来自第 1 周）

- **PostgreSQL 16**——存储论文元数据和内容
- **FastAPI**——提供论文检索 REST API 端点
- **Apache Airflow**——工作流编排与调度
- **Docker Compose**——服务编排与网络管理

## 流水线架构

```text
arXiv 搜索查询 → 限流 API 调用 → 下载 PDF → Docling 解析 → 数据库存储
       ↓               ↓              ↓            ↓             ↓
   日期筛选      →   重试逻辑    →    缓存    →  结构化提取  → upsert 逻辑
   分类筛选      →   错误处理    →    验证    →  内容提取    → 事务处理
   结果限制      →   3 秒限流    →  大小检查  →  元数据      → 关系维护
```

## 性能特征

**第 2 周系统能力：**

- **arXiv API**：约 20 篇论文/分钟（遵守 3 秒限流要求）
- **PDF 处理**：每篇 2～5 秒（取决于 PDF 的复杂程度）
- **数据库存储**：约 100 篇论文/秒（批量操作）
- **错误处理**：即使个别任务失败，也能优雅地继续处理
- **成功率**：论文获取超过 95%，PDF 解析为 80%～90%

- 系统会妥善处理失败并继续运行
- 对学术论文 PDF 而言，80%～90% 的成功率属于正常水平
